# On-device VITON for Android: roadmap

**Target:** a standalone native Java app with minSdk 26 (Android 8.0). The product is photo try-on (a person photo plus a garment photo), upper-body first. Everything runs on device with LiteRT.

## Device tiers

| Tier | Devices | Model | Backend | Latency target |
|---|---|---|---|---|
| A | 7+ GB RAM, Android 12+ | 512x384 (later: few-step diffusion) | GPU / NPU | < 500 ms |
| B | 64-bit, 4+ GB RAM, Android 10+ | 512x384 | GPU | < 1.5 s |
| C | Android 8-9 era, 32-bit or < 4 GB RAM | 256x192 micro model, INT8, < 20 MB | CPU (XNNPACK), GPU if GLES 3.1 | 2-4 s |

Supported ABIs are `arm64-v8a` and `armeabi-v7a`. Keep Tier C peak memory under 150 MB. Tiers are assigned in `DeviceTierClassifier`.

## Phases

### 0. Scope and licensing (weeks 1-2)
- Lock the product scope, the tier budgets and the reference devices. Include at least one Android 8 phone with a Snapdragon 625/660 and 3 GB RAM, and one with a Mali-G71 GPU.
- **Licensing:** VITON-HD, DressCode and most public try-on weights are non-commercial. Plan licensed or self-collected paired data, or synthetic data generated by a teacher model.

### 1. Python reference pipeline (weeks 2-6), milestone M1
- Preprocessing: pose (MediaPipe), human parsing (SCHP), garment mask.
- Teacher models: HR-VITON or GP-VTON (warping-based) and CatVTON or IDM-VTON (diffusion, the quality ceiling).
- Metrics: FID, KID, SSIM and LPIPS on the benchmark set, plus a set of real phone photos.

Done (`ml/vton`, CPU-only, tested in CI): dataset loader and layout checker for the VITON-HD
layout, preprocessing (MediaPipe pose and 6-class parsing, garment masks), and SSIM, LPIPS,
FID and KID with an evaluation CLI.

Still needs the phase 0 decisions: which dataset (licensing), converting it to the common
layout, and GPU time for the teacher models.

### 2. Mobile student distillation (weeks 6-12)
- A parser-free student in the style of PF-AFN and DM-VTON, so it needs only the person and garment images at inference time.
- MobileNetV3 or EfficientNet-lite encoders, appearance-flow warping and a lightweight generator.
- Two student models: Tier C micro (256x192) and Tier A/B (512x384).
- Quantization-aware training (QAT) from the start. Keep float32 model inputs and outputs (see `android/app/src/main/assets/models/README.md`).
- **Risk: `grid_sample`.** Replace it with gather and matmul inside the model, or with a GLES 3.1 compute shader. Validate on Adreno 5xx and Mali-G71 in the first week.

### 3. Conversion and benchmarking (weeks 9-12, overlaps phase 2), milestone M2
- PyTorch → ai-edge-torch → LiteRT, then test the GPU delegate and XNNPACK on each reference device.
- Don't use NNAPI: it's missing on Android 8.0 and deprecated since Android 15.
- Exit criteria: the latency and size budgets for every tier are met, and the quality loss against the teacher is within the agreed delta.

### 4. Android MVP, native Java (weeks 12-19), milestone M3
Already set up in `android/`:
- `device/`: tier classification, cached in SharedPreferences.
- `ml/LiteRtRunner`: GPU delegate with automatic CPU fallback, and memory-mapped models.
- `pipeline/`: pose check → crop → inference → composite, all on a single inference thread.
- `ui/`: CameraX capture, gallery pickers and the result view.

Still to do:
- Calibrate the first-run benchmark thresholds (`TIER_A_MAX_MS`, `TIER_B_MAX_MS` in
  `DeviceTierClassifier`) from device reports once the phase 2 student exists.
- Deliver Tier A/B models through Play Asset Delivery.
- Add garment masking.
- Keep lower-body clothing (trousers, skirts) from the original. The segmenter has one
  "clothes" class, so this needs a split at the hips using the pose landmarks.

Done: a first-run device benchmark. A MobileNetV2-0.5 reference workload is timed on CPU and
GPU once per OS build. The GPU is used only if its output matches the CPU and it's faster.
RAM and 64-bit stay hard gates; measured speed decides the rest.

Done: a composite that keeps face, hair and hands (`PreserveSegmenter` + `MaskOps`). It keeps
face, hair, accessories, hands (body skin inside pose-based hand circles) and background
beyond a 6% margin from the person, with feathered edges.

### 5. Quality hardening (weeks 19-23), milestone M4
- Failure cases: crossed arms, occlusion, long hair, loose garments, low light, and a range of skin tones.
- Stress tests for low RAM, thermal throttling and backgrounding during inference on Android 8.
- Guide the user to retake bad photos instead of producing a bad result.
- Optional super-resolution for Tier C (256x192 → 512x384). Closed beta.

### 6. Expansion
- A few-step diffusion model for Tier A only.
- Lower-body garments and dresses.
- Low-resolution real-time AR preview.
